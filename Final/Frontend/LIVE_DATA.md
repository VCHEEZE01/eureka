# 기준 HTML에서 실제 타겟 탐색

서비스는 `reference-pages/`의 기존 디자인을 사용하는 단일 HTML입니다. React 화면은 이 사용자 흐름에 사용하지 않습니다.

```sh
npm run build:single
```

기본 출력 `eureka-공유용.html`은 **live 모드**입니다. 백엔드 실행 후 `http://localhost:8000`에서 열면 같은 origin의 API를 호출합니다. 파일을 직접 열면 서버 주소를 안내하고 수집하지 않습니다. 디자인 데모 빌드 옵션과 결과·상세의 샘플 데이터는 제거했습니다. 기본 번들에는 index/config/loading/result/detail 다섯 화면만 포함되며 아이디어·개인화·조합 경로는 잠겨 있습니다.

## 탐색과 진행 중 결과 확인

나이대·성별·직업·장소 중 최소 두 항목을 입력하고 탐색하면 POST `/collections`에 `{target:{age,gender,jobs,places}}`를 보냅니다. 직업·장소는 Enter로 각각 최대 다섯 개, 키워드당 서른 자까지 등록합니다. 성별 값은 여성/남성입니다. 입력 조건은 검색과 근거 판별에 사용되며 작성자의 신원이나 모든 속성을 인증하지 않습니다.

서버 작업 ID를 받은 뒤 GET `/collections/{id}`로 실제 단계와 처리 건수를 확인합니다. 최신 정책 `target_match_policy: "evidence_v2"`의 실행만 현재 결과로 받습니다. 타겟 판정은 원문의 맥락과 입력 조건의 연관성을 확인하며, 입력 키워드가 그대로 나와야만 하는 방식이 아닙니다. 이전 정책 또는 정책 필드가 없는 저장 실행은 GET 복원하더라도 결과·집계를 노출하거나 계속 폴링하지 않고 명시적인 새 탐색을 안내합니다.

주화면은 검색한 주제 수와 누적 수집·분석·발견 불편·타겟 확인을 보여줍니다. 대표 숫자는 **발견한 불편 N건**과 **타겟 확인 문제정의 M개**로 구분합니다. 회차·전체 검색 조합 수는 사용자에게 완료해야 할 할당량으로 보여주지 않고 검색 상세에 둡니다. 회차 완료는 전체 검색 완료와 다릅니다. `coverage`가 전체 카탈로그의 진행/남은 항목·주제·검색 의도 범위를 보여주고, `stop_reason`은 회차 예산·시간·AI 예산·카탈로그 소진·실패를 구분합니다. `counts`는 이번 회차, `cumulative_counts`는 같은 조건과 계획 버전의 전체 누적입니다. 누락된 값은 숫자를 추정해 채우지 않습니다.

수집한 자료를 먼저 분석하는 기본 흐름이며, 처리 한도 이후의 추가 탐색은 선택 사항입니다. 완료 또는 실패한 실행이 `has_more: true`이고 서버 `can_resume`가 허용하면 **추가 탐색** 버튼이 POST `/collections`에 `{target, resume_from: "이전 실행 ID"}`를 보냅니다. 응답의 새 실행 ID를 저장하고 다음 범위를 조회합니다. 남은 검색 항목이 0개여도 미판별 원자료나 미생성 후보가 있으면 `has_more`가 참이며, 이때 다음 회차는 남은 판별·문제정의 자료를 처리합니다. 화면은 자동으로 예산을 소진하며 여러 회차를 시작하지 않습니다. 요청 직후 이전 문제 목록을 비우고 새 작업의 응답만 받아 다른 실행 결과가 섞이지 않게 합니다.

로딩 화면의 **현재까지 발견한 불편 보기**로 완료 전 결과를 열 수 있습니다. 결과 화면도 같은 실행의 GET 폴링을 계속 받아 불편과 문제정의를 갱신합니다. 화면 이동은 새 POST를 만들지 않습니다. 진행 중 빈 문제정의 목록은 최종적인 불편 없음으로 표시하지 않습니다. 실패하더라도 해당 실행에서 이미 확인한 결과는 볼 수 있습니다.

서버 `current_plan_version`과 실행 `plan_version`이 다르면 이전 탐색 기록임을 안내합니다. 완료/실패한 이전 기록의 **넓어진 범위로 다시 탐색** 버튼만 명시적으로 `{target}`을 POST하며 `resume_from`은 생략합니다. 이전 실행에 새 예산이 적용된 것처럼 표시하지 않습니다.

## 결과에 표시하는 근거

- 주화면에는 누적 수집·분석·발견 불편·타겟 확인·미확인·타겟 확인 불편·문제 건수를, 상세에는 이번 처리 수치를 표시합니다. 충돌·검색/판별 실패와 문제 생성·검수 실패 건수, 형식 재시도 횟수도 0보다 큰 실제 값이 있을 때 표시합니다.
- `query_results`의 실제 검색어, 주제·의도·매체, 성공/실패, 반환 건수와 중복 제거 후 신규 저장 건수. `queries`의 계획 목록을 실행 결과로 바꾸어 표시하지 않습니다.
- `exclusion_reasons`와 중복 제거된 경고를 펼쳐 확인할 수 있습니다.
- `review_candidates`는 **발견한 불편 · 타겟 확인 필요**라는 주화면 영역에서 기본으로 펼쳐 보여주며 문제정의 목록과 분리합니다. 미확인/충돌과 판정 사유·실제 출처 링크를 보여주며 문제 수에 더하지 않습니다. 서버가 반환한 전체 자료 수를 표시하고 20건씩 페이지를 넘겨 모두 볼 수 있습니다. 분석 중 갱신되어도 현재 페이지를 유지합니다.
- 해당 실행이 반환한 `problems`·`reviews`만 문제 목록·상세에 표시합니다. 이어 수집 응답은 같은 시리즈의 유효한 기존 문제와 새 문제를 합친 누적 결과입니다. 이번 회차 `counts.problems`는 새로 생성한 문제 수, 누적 `cumulative_counts.problems`는 현재 누적 결과 수입니다. 게시 보류와 AI 검수 사유, 분모·표본 부족·근거 필터는 유지합니다.

검색어·서버 사유는 텍스트로 출력하며, 원문 URL은 http/https만 링크합니다. 빈 결과는 실패와 구분하고, 탐색이 진행 중이면 결과가 계속 갱신됨을 안내하고, 종료 후 남은 자료가 있을 때만 추가 탐색을 선택할 수 있습니다. 데이터가 없다고 샘플을 대신 표시하지 않습니다.

## 새로고침과 오류 복구

실행 ID는 세션에 저장됩니다. 새로고침은 GET으로 복원하고 명시적 새 탐색만 POST합니다. POST 응답 전에 연결이 끊겼으면 자동으로 재요청하지 않습니다. 사용자가 재시도를 선택하면 저장된 조건과 `resume_from`을 보존합니다. 네트워크 오류의 재시도는 기존 ID 조회, 실패한 실행의 새 탐색은 같은 조건의 새 POST입니다. 남은 범위만 원하면 **추가 탐색**을 사용합니다.

## 명시적 오프라인 검토 파일

실제 JSON을 지정한 공개·검토 스냅샷만 별도로 생성할 수 있습니다. 입력 조건을 변경해도 새 수집하지 않는 고정 자료임을 안내합니다.

```sh
npm run build:single -- --data problems.json --mode published --out eureka-공개표본.html
npm run build:single -- --data problems.json --mode review --report problems.report.json --out eureka-검토용.html
```

입력은 백엔드 `Problem[]` JSON입니다. 공개 표본 모드는 게시 기준 미달 객체를 거부합니다. 검토 보고서가 없으면 AI 검수 결과 미포함으로 표시합니다. 원문 주소는 실제 `source_url`만 사용합니다.

검증: `node --test scripts/tests/*.test.mjs`, `npm run build:single`. Node 회귀 테스트는 모의 응답을 사용하므로 실제 검색 API·Gemini의 동작과 판별 품질을 검증했다는 뜻은 아닙니다.
