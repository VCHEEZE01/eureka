# 온보딩 타겟 수집

2026-09-13 사용자 결정: 나이대·성별·직업·장소 입력에 맞게 수집한다. 앞으로 변경되는 설계와 검증 상태는 `docs/eureka-agent-guide.html` 및 바탕화면의 `유레카_에이전트_설계지도.html`에 함께 반영한다.

## 사용자 흐름

사용자가 선택한 기준 디자인은 `Final/Frontend/reference-pages/`다. React/Next 화면은 기본 유레카 웹으로 사용하지 않는다.

온보딩에서 네 항목 중 최소 두 항목을 입력하고 탐색을 누른다. 서버는 타겟별 수집 실행을 만들고 검색 API 호출, 불편 판별, 근거 집계, 문제정의·AI 검수를 수행한다. 화면은 실제 실행 상태를 조회하다가 그 실행의 결과를 보여준다. 실패와 자료 없음은 별도로 표시한다.

검색 조건에 ‘30대’나 ‘여성’이 들어간 것은 검색 결과 작성자의 나이·성별이 확인됐다는 뜻이 아니다. 집계 라벨은 원문에 명시된 정보를 사용한다. 타겟을 바꿀 때 이전 타겟 자료를 새 수집 결과로 재사용하지 않는다.

## 확정 사항과 구현 선택

사용자가 확정한 사항은 네 타겟 항목에 따른 수집, 기존 공유용 디자인 사용, 아이디어 잠금, 변경 사항의 시각화 반영이다. 최소 두 항목·키워드 칩 등 기존 입력 계약은 유지한다.

여러 직업·장소를 조합하는 방법, 카테고리별 검색어·출처 배분, 호출·처리량 상한, 재사용 기간은 구현 정책이다. 자동으로 사용자 승인된 기획 값으로 승격하지 않는다. 현재 구현은 입력한 필드들을 검색어에 함께 넣고 직업·장소의 여러 값은 쿼리를 나누어 실행한다.

## 실행

```sh
cd /Users/minkyu/Documents/GitHub/eureka/Final/Frontend
npm run build:single
cd ../Backend
LLM_DRY_RUN=false .venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

브라우저에서 `http://localhost:8000`을 연다. API 서버가 기본 live `eureka-공유용.html`을 그대로 제공한다. 기존 `localhost:3000`의 React 화면은 사용하지 않는다. 키는 `.env`에서 읽고 브라우저로 전달하지 않는다. 파일을 직접 연 경우에는 수집 서버 주소를 안내한다.

- POST `/collections`: `{target:{age,gender,jobs,places}}`. 실행 ID와 현재 상태를 반환한다.
- GET `/collections/{id}`: 실제 상태·단계·검색 계획·건수·검토 결과 조회. 조회만으로 수집하지 않는다.
- `data/collections/{id}/run.json`: 정규화된 타겟, 실행 상태, 실제 쿼리·출처, 처리 건수, 결과·검수 기록.
- 같은 폴더의 `corpus/`: 해당 실행에서 수집한 원문·판정·후보. API 검색 응답마다 원문을 저장하므로 중간 실패에도 이미 받은 자료는 남는다.
- 공개 목록 GET `/problems`는 기존 승인 저장소만 읽는다. 타겟 수집의 검토 초안은 공개 저장하지 않는다.

## 현재 구현 상한과 재사용

직업과 장소가 한 개씩이거나 한쪽이 미입력이면 다섯 카테고리에서 기본 5쿼리다. 각 목록이 최대 다섯 개일 때 25조합 × 5카테고리 = 최대 125쿼리다. 쿼리당 한 검색 endpoint를 호출하고 최대 10건을 받는다. 재시도는 요청당 최대 세 번이므로 검색 HTTP 시도 상한은 15~375회다.

수신 원문은 중복 제거 후 전량 보존한다(응답 상한 기준 최대 50~1,250건). 타겟 문구가 확인된 원문 중 카테고리당 최대 10건, 전체 최대 50건을 판별 대상으로 선정한다. 문제 초안은 최대 5개다. LLM 논리 호출 상한은 15회이고 HTTP 재시도 상한은 실행 기록의 `limits`에 별도로 담긴다. 실행 기본 제한은 600초, 동시 실행은 하나다. 같은 조건의 진행 중 실행과 완료 후 3,600초 이내 실행은 재사용한다. 실패 실행의 명시적 재시도는 새 ID를 발급한다. 검색 계획 버전이 바뀌면 이전 완료 결과를 재사용하지 않는다.

검색 분야 키워드는 제한된 사전 표본을 쓴다. 금융·헬스케어는 네이버 뉴스, 나머지 카테고리는 지식iN·카페·다음 블로그를 나누어 쓴다. 분야·출처 배분과 상한은 임시 구현 정책이며 사용자 트래픽에 적합한 운영 정책으로 검증된 것은 아니다.

## 타겟 관련성 검사

검색 API가 입력 문구와 연관성이 확인되지 않는 자료도 반환하는 것을 실호출에서 발견했다. 따라서 쿼리 생성과 별개로 제목·스니펫의 문구를 대조한다. 입력 필드끼리는 모두 확인돼야 하며 직업·장소 목록 안에서는 하나 이상 확인하면 된다. Unicode·공백을 정규화하고 성별의 여성/여자·남성/남자 표현을 대조한다. 문구를 확인하지 못한 자료는 원문에 보존하되 판별·문제 생성에서는 제외한다. 판별 후 명시적 연령·성별 라벨이 타겟과 다른 경우도 후보에서 제외한다.

`target_match_policy=input_mentions_v1`이 새 실행 정책이다. 과거 실행은 `not_checked`로 읽고 현재 타겟 결과로 노출하지 않는다. 과거 원문·생성 기록을 고쳐 검증된 것으로 바꾸지 않는다.

`counts`는 수신 `fetched`, 중복 제거 저장 `collected`, 문구 확인 `target_matched`, 연관 미확인 `target_unconfirmed`, 판별 선정 `selected`, 미선정 `unselected`, 실제 판별 `judged`, 판별 실패 `judge_failed`, 명시적 속성 불일치 `target_conflicts`를 구분한다.

## 실제 실행 검증

최종 실행 `col-21487dbac1b941b9a0320966`은 브라우저의 **같은 조건으로 다시 탐색** 버튼에서 시작했다. 타겟은 나이대 30대·직업 군인, 성별·장소는 미입력이다.

| 단계 | 실제 결과 |
| :-- | --: |
| 타겟이 포함된 검색 요청 | 5개 성공 / 0개 실패 |
| API 수신·중복 제거 저장 | 31건 |
| 제목·스니펫 타겟 문구 동시 확인 | 3건 |
| 연관 미확인·보존 | 28건 |
| 규칙 통과 후 Gemini 판별 | 2건 |
| 실제 불편 후보 / 문제정의 | 0건 / 0건 |
| Gemini 논리 호출 | 2회 |

첫 연결 실행 `col-f660697bb8574be9b80b85dc`에서는 같은 31건에서 문구 검사를 하지 않아 관련성이 확인되지 않는 문제 초안 세 개가 생성됐다. 이 관측으로 타겟 검사와 과거 결과 차단을 추가했다. 첫 실행은 개선 전 이력으로만 보존한다. 과거 회의록 파일럿도 이번 타겟 수집의 성공 사례로 계산하지 않는다.

브라우저에서 입력 → 실제 단계 조회 → 새 실행의 빈 결과를 확인했다. 새로고침 시 기존 ID를 GET으로 복원하고 새 실행을 만들지 않았으며, 미검사 과거 실행은 재탐색을 안내했다. 수집 범위와 제외 사유는 접힌 설명으로 제공한다.

합성 테스트는 검색·LLM 응답만 대체하고 실제 수집→판별→묶기→근거→검토 문제정의 코드를 끝까지 실행한다. 이는 후보가 생겼을 때의 데이터 연결 검증이며 실데이터 품질이나 게시 승인을 증명하지 않는다.


## 자동 검증

- 백엔드: `.venv/bin/python -m pytest -q` — **561개 통과**. 이 중 신규 타겟 수집 40개: 네 필드 검증·조합, 문구 검사, 원문 보존, 실행 격리, 실패와 빈 결과 구분, 알려진 속성 불일치 제외, 과거 실행 차단, 중복·시간 제한·worker 생존 확인, 양성 전체 생성 경로.
- 프론트: `node --test scripts/tests/*.test.mjs` — **17개 통과**. 입력 POST·실제 단계 GET·새로고침 복원·타겟 변경·명시적 재시도·이전 정책 결과 차단·상세 데이터·출처·검토 사유·빈 결과와 페이지 번호·안내 펼침을 확인한다.
- `npm run build:single` 및 `git diff --check` 통과. 라이브 출력은 사용자 기준 디자인이다.

신규 worker는 실행별 파일 잠금으로 생존·중복 실행을 확인한다. 초기 import 유예를 두고, 종료가 확인되지 않은 실행을 임의로 재시작하지 않는다. timeout과 종료 상태는 별도로 기록한다. 과거 실행의 저장 파일은 변경하지 않았다.

## 결과 해석

문구가 함께 등장해도 같은 작성자의 경험인지, 계획·인용·부정 표현인지까지 입증하지는 못한다. 본문 전체를 읽지 않아 관련 자료가 스니펫에 드러나지 않으면 빠질 수 있다. 직업·장소 의미 관계 판별, 동의어와 연령 범위 확장, 검색 분야 배분, 충분한 표본 확보는 후속 품질 검증 사항이다.

실행 완료는 공개 게시나 내용 검수 통과를 뜻하지 않는다. 생성 결과가 있더라도 근거 기준 미달·AI 검수 보류·사람 검수 미승인을 구분해 보여준다. 공개 문제 저장소에 자동 게시하지 않는다. 자료가 부족하다고 기준을 낮추거나 예시 문제로 대체하지 않는다.
