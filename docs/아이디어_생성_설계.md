# 아이디어 생성 — 플랫폼 × 유형 축 정의

**대상**: 플랫폼(웹/모바일 앱) × 아이디어 유형(실용/재미/수익) 6조합이 실제로
무엇을 바꾸는지 정의한다. 이전까지 이 정의는 저장소 어디에도 없었다 — 코드에서 두
축은 프롬프트 헤더 두 줄에만 쓰였고 아이디어 내용에는 영향이 없었다.

**구현**: `Final/Backend/app/ideas/axes.py`가 이 문서의 표를 코드로 옮긴 것이다. 표가
바뀌면 그 파일도 같이 고칠 것 — 여기가 문서, 거기가 소스.

**관련 문서**: [IDEA_GENERATION_HANDOFF.md](IDEA_GENERATION_HANDOFF.md) (IA·프롬프트
규칙), [IDEA_DETAIL_SPEC.md](IDEA_DETAIL_SPEC.md) (화면 렌더 사양),
[트렌드_백엔드_설계.md](트렌드_백엔드_설계.md) 7절 (API 계약 원안)

## 0. 기간 라벨 정규화 (먼저 짚고 갈 것)

코드(`v1-trend-incubator.html`)와 문서가 기간 라벨을 다르게 써왔다:

| | day | week | month |
|---|---|---|---|
| 화면 칩 라벨 | 하루 | 일주일 | 한 달 이상 |
| 예전 문서 표기 | 1일 | 일주일 | 한달 |

**내부 키는 `day`/`week`/`month`로 통일한다.** 백엔드는 두 표기 모두 별칭으로
받는다(`app/ideas/axes.py`의 `PERIOD_ALIASES`). 이 세 기간은 로드맵이 아니라
서로 독립된 완성본이다 — 자세한 규칙은 HANDOFF 문서 참고.

## 2. 유형 축

| | 실용(편의) | 재미 | 수익(비즈니스) |
|---|---|---|---|
| 내부 키 | `utility` | `fun` | `business` |
| 핵심 각도 | 반복되는 번거로운 일 하나를 자동화. 줄어든 단계가 눈에 보여야 함 | 캡처해서 보내고 싶은 결과물. 해보기→공유→또 해보기 고리 | 누가 왜 돈을 내는지가 구조에 드러남. 무료/유료 화면이 다름 |
| 금지 | 게임 요소·수익 모델 | — | **가격·매출·시장 규모 숫자를 지어내지 않는다** |
| IA 반영 | depth1 순서: 입력 → 처리·결과 → 저장 | 마지막 depth1은 반드시 결과 공유 화면 | depth1 중 하나는 거래(판매/예약/문의) 화면 |
| MVP 방향 | 설정 화면 없이 기본값으로 핵심 동작 하나를 끝까지 자동화 | 회원가입 없이 30초 안에 결과 + 이미지 카드 저장·공유 | 결제는 외부 링크/문의 폼으로 대체, 유료 전환 지점 1곳 명시 |
| 디자인 톤 | 정보 밀도 높은 군더더기 없는 UI | 과감한 색·애니메이션, 손맛 인터랙션 | 신뢰감 있는 절제된 UI |
| 이름 짓기 | 기능이 이름만 봐도 보이게 | 말장난·밈으로 입에 붙게 | 신뢰가 가는 담백한 이름 |
| stack 추가 | (없음) | Framer Motion, html2canvas | Supabase(인증·데이터), 토스페이먼츠/외부 결제 링크 |

## 3. 6조합 — 조합별 성격 메모

두 축을 곱하기만 하면 결과가 비슷해질 위험이 있다(특히 "재미"는 플랫폼 영향을
덜 받는다). 아래 한 줄을 프롬프트 맨 앞에 강제로 넣는다(`axes.COMBO_NOTES`).

| | 실용 | 재미 | 수익 |
|---|---|---|---|
| **웹** | 링크를 열어 붙여넣기 한 번으로 끝나는 도구. 계정 없이 결과가 나오고 결과 주소를 저장해 두면 다시 쓴다. | 결과 주소 자체가 공유 자산이다. 남의 결과 페이지를 열어보는 것만으로도 재미가 있어야 한다. | 검색·광고로 들어온 방문자를 문의·예약으로 넘기는 랜딩형 구조. 판매자용 관리 화면이 따로 있다. |
| **모바일 앱** | 현장에서 꺼내 3초 만에 기록하고 닫는 앱. 나중에 몰아서 정리하는 화면이 따로 있다. | 카메라나 위치로 지금·여기를 찍어 만드는 놀이. 만든 결과는 스토리 비율 카드로 나간다. | 현장에서 바로 주문·예약·정산이 일어나는 접점. 알림이 매출로 직결된다. |

## 4. 추천 AI — 기간별 고정 화이트리스트

**LLM이 자유롭게 툴 이름을 만들지 않는다.** 사용자가 이 pill을 보고 실제로
가입·결제하러 가므로, 존재하지 않는 툴이나 낡은 모델명이 나오면 안 된다
(예전 하드코딩값 "Claude 3.5 Sonnet"이 이미 낡은 예). **버전·모델명은 절대
넣지 않는다** — 이름과 역할만 둔다.

> 2026-09-19: 추천 기준이 **플랫폼×유형 축에서 개발 기간으로 바뀌었다.**
> 기간이 길수록 손으로 치는 도구에서 대신 짜주는 에이전트로 넘어간다.
> 기존의 축 기반 표(`AI_TOOL_COMBO`)와 `pick_ai_tools()`는 제거했다 —
> 두 체계를 함께 두면 화면과 응답이 어긋난다.

| 기간 | 내부 키 | 추천 AI |
|---|---|---|
| 하루 | `day` | ChatGPT · Gemini · Claude · Google AI Studio |
| 일주일 | `week` | Antigravity · Cursor |
| 한 달 이상 | `month` | Claude Code · Codex |

표는 `axes.AI_TOOL_BY_PERIOD`, 조회는 `axes.tools_for_period(period_key)` /
`axes.tools_by_period()`. 아이디어 캐시 키에 `period`가 없고 기간별 프롬프트
3벌을 한꺼번에 싣는 것과 같은 이유로, **AI 목록도 3기간 전부를
`IdeaSpec.ai_tools_by_period`에 담아 한 번에 내려보낸다.** `ai_tools` 필드는
`day` 사본으로 남겨둔다(기존 소비자 호환용).

## 5. API 계약

```
POST /api/trends/{keyword_id}/ideas
GET  /api/trends/{keyword_id}/ideas?platform=..&type=..&period=..&count=..
```

요청 바디(POST): `{ platform, type, period, count, refresh }` — 프론트 칩 라벨
그대로 받는다(별칭 정규화는 백엔드가 함).

오류 코드는 [트렌드_백엔드_설계.md](트렌드_백엔드_설계.md) 7절 규약을 그대로
따른다: `invalid_input`(400) / `keyword_not_found`(404) / `snapshot_not_ready`(503)
/ `internal_error`(500). LLM 실패·오프라인은 오류가 아니라 `source: "fallback"`으로
200을 반환한다(트렌드 탭의 `is_dummy` 관행과 동일).

**캐시 키에 `period`가 없다** — 응답에 `day`/`week`/`month` 프롬프트를 전부
담으므로 기간 칩을 바꿔도 재요청이 필요 없다. 자세한 필드는
`Final/Backend/app/schemas/idea_models.py` 참고.

## 6. 계약 변경 — 팀 공지

`app/agents/idea_agent.py`(④ 담당)를 v1 계약으로 재작성했다. v0의
`IdeaInput`(`Problem` + `UserCondition` 기반)은 `git tag v0-pre-pivot`에만
남아 있다. `app/schemas/models.py`는 건드리지 않았고, v1 `Idea` 스키마는
`app/schemas/idea_models.py`에 새로 뒀다 — `app/trends/`가 `trend_models.py`를
따로 둔 것과 같은 이유다.
