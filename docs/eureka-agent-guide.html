② 해석기 · 실제 경험을 먼저 확인

글의 목적을 먼저 구분한다.
실제 글쓴이의 구체적인 사건 + 막힌 지점이 확인되면 불편 후보다.

② 출력 검증 · 모델 응답을 그대로 믿지 않음

지불 신호는 LLM에게 산출시키지 않고 별도 PAYMENT_SIGNALS 규칙으로 계산합니다. 요약에는 집계성 수치 제거, 길이 제한, 원문 복제 비율 검사도 적용합니다. 이런 검사가 모든 의미 왜곡을 찾아내는 것은 아닙니다.

호출·파싱 실패는 낮은 확신도로 강등해 묶기 승격에서 제외합니다. 상한 초과분·보류 기록은 보존합니다. 기존 판정 재사용·재판정 버전 선택은 파일럿 보고서가 지적한 운영 점검 대상입니다.

③은 초안 생성 후 별도 AI 검수 요청으로 모든 사실 주장을 원문에 대응시킵니다. “오랜만에 담당”을 “업무 복귀”로 바꾸거나 비유를 실제 기술 사용으로 단정하는 과대추론도 보류하도록 지시합니다. LLM 생성·검수가 실패하거나 계약을 충족하지 못하면 hold 사유를 반환합니다. 목업 데이터가 실데이터 경로를 대신하는 동작도 허용하지 않습니다.

반복 실행과 사람 검수 · 테스트 통과와 품질은 별개

파일럿에서 보강 후 불편 여부는 26/26건 일치했지만 양성은 2건뿐입니다. 강도 일치 26건에는 음성의 null 24건이 포함돼 양성 추출 정확도를 뜻하지 않습니다. 나이·성별·지불 신호도 양성 표본을 검증한 결과가 아닙니다.

문서 기준은 초기 게시 전 사람 검수입니다. 자동 게시 기준을 통과했다는 사실과 사람이 내용까지 승인했다는 사실은 구분해야 합니다. 검수 범위·종료 조건은 미결정이며, 사용자에게 하지 않은 검토를 했다고 표시하면 안 됩니다.

완료의 기준은 ‘상세페이지가 읽을 정보’

입력값의 실제 검색 전달, 작업 ID에 따른 상태·결과 연결을 검증했습니다. 실제 재실행은 후보 0건이며, 후보가 있을 때의 상세 생성 연결은 명시적인 합성 자료로 전체 경로를 확인했습니다.

A

타겟 수집 작업 → 격리 코퍼스 → 문제정의 이번 구현

POST 요청으로 입력 조건을 받아 실제 검색 쿼리를 만들고 수집 작업을 실행합니다. 작업별 자료를 판별·집계·문제정의로 연결하고 결과와 보류 사유를 작업 ID로 재조회합니다.

확인: 입력 조건의 검색 반영 · AND/OR 조합 · 작업별 코퍼스 격리 · 실제 진행 상태 · 생성 실패/보류 사유 · 수치/출처 대조
B

기준 디자인의 입력·진행·실행 결과 연결 이번 연결

기준 config의 네 필드가 작업 생성 요청으로 전달되고 loading이 실제 서버 단계를 확인합니다. result·detail은 해당 실행 결과만 읽습니다. React는 사용하지 않으며 아이디어·개인화는 잠금을 유지합니다.

확인: 입력 → POST → 상태 GET → 동일 작업 결과·상세 · 대기/실행/실패/빈 결과/검토 보류 · 출처·필터·분모 · 기존 디자인
C

새 표본으로 판별·요약 검증 후속 제안

커뮤니티·질문형 검색 표본으로 실제 경험 비율을 점검합니다. 파일럿의 보류 요약과 역할 오인식을 사람 정답과 비교하고, 재판정 버전을 분리합니다.

확인: 광고/가정 제외 · 잘린 글 추론 방지 · 별도 표본 평가 · 출처 편중 · 대표 근거 요약과 원문 대응
D

운영 상한·소스·공개 정책 검증 남은 운영 결정

요청당 검색·LLM 비용, 동시 실행·재시도 상한, 직업·장소의 카테고리 매핑과 활성 소스 범위를 검증합니다. 게시 전 사람 검수·출처 정의·기준 적정성도 별도 판단합니다.

확인: 실행 로그·상한·실패 사유 · 검색 조건과 확인 속성 구분 · 공개/검토 분리 · 검수 기록 · 검증된 소스만 활성화
