## 읽는 순서

### 1️⃣ 프로토타입 만져보기 · 10분

**파일: `eureka-공유용.html`**

설명을 읽기 전에 **직접 눌러보는 게 제일 빠릅니다.** 화면 13개가 전부 동작합니다.

이 순서로 눌러보세요.

1. 랜딩에서 **문제 둘러보기**
2. 소스 두어 개 체크하고 **시작하기** → 진행 화면이 잠깐 뜹니다
3. 문제 카드 아무거나 클릭 → **근거와 출처**를 봐주세요
4. **아이디어 보기** 클릭
5. 뒤로 가서 문제 목록 → 카드 우상단 **조합에 담기** 2개 체크 → 하단 **문제정의 조합하기**
6. 로그인(아무 이메일) 후 **개인화하기** 까지

> 💬 **여기서 이야기할 것**
> 흐름이 자연스러운가? 어디서 막히거나 헷갈리는가?
> 화면에 없어서 아쉬운 게 있는가?

---

### 2️⃣ 에이전트가 뭘 하는지 보기 · 15분

**파일: `에이전트_흐름도.html`**
**웹 링크: https://claude.ai/code/artifact/3656fcc8-f3b5-4a30-bd85-19da0300b6df**

방금 만져본 화면 **뒤에서** 뭐가 도는지 그림으로 정리한 것입니다.

맨 위 그림 하나만 봐도 절반은 이해됩니다 — **에이전트는 네 개뿐**이고,
그중 뒤의 두 개를 입력만 바꿔서 재사용합니다.

| 순서 | 그림 | 요점 |
| :-- | :-- | :-- |
| 1 | 에이전트 넷 | 수집 → 해석 → 문제정의 → 아이디어 |
| 2 | 축이 두 개 | 미리 돌려두는 것 / 사용자가 기다리는 것 |
| 3 | 문제를 만드는 과정 | 7단계 후 게시·보류·병합으로 갈림 |
| 4 | 기다리는 동안 | 진행 상태를 화면에 흘려보냄 |
| 5 | 규칙 두 가지 | 도구 경유 · 숫자는 AI가 못 만듦 |

> 💬 **여기서 이야기할 것**
> 맨 아래 **논의 카드 6개**가 이번에 정할 것들입니다.
> 특히 **"묶기를 어떻게 할까"**와 **"검수는 누가 하나"** 두 개가 핵심입니다.

### 3️⃣ 무엇을 만들 건지 확인 · 15분

**파일: `Eureka_PRD_v2.md`**

기능 정의서입니다. 전부 읽지 마시고 **이 세 곳만** 봐주세요.

- **5절 MVP Feature List** — F00~F10, 한 페이지
- **6절 Functional Requirements** — 기능별 상세. 맡으실 기능만
- **10절 TBD** — 아직 안 정한 것 15개

**같이 보면 좋은 그림: `flow_diagram_abstract.png`**
화면이 어떻게 이어지는지 한 장으로 그린 것입니다.
색깔이 3가지 개인화 포인트를 나타내고, 주황 점선은 사용자가 나가는 지점입니다.

> 💬 **여기서 이야기할 것**
> 10절 TBD 중에 **지금 정할 수 있는 게 있는지.**
> 특히 데이터 소스는 API 키 발급에 시간이 걸려서 빨리 정하는 게 좋습니다.

## 프로토타입 돌려보려면

소스를 직접 고쳐보실 분만 해당됩니다.

```bash
cd TAEYUN/prototype
npm install
npm run dev          # http://localhost:3000
```

공유용 HTML을 다시 만들려면:

```bash
npm run build:single # TAEYUN/eureka-공유용.html 생성
```
