# 유레카 — 시작 프롬프트 가이드

**깃에서 받아온 다음, 이 순서대로 하면 됩니다.**

팀원이 처음 합류할 때 · 다른 컴퓨터에서 이어서 작업할 때 · 새 AI 세션을 시작할 때 쓰는 문서입니다.

---

## STEP 1 — 받아오기

```bash
git clone -b taeyun https://github.com/VCHEEZE01/eureka.git eureka-taeyun
cd eureka-taeyun
```

받으면 이런 구조입니다.

```
eureka-taeyun/
├─ README.md
└─ TAEYUN/          ← 전부 여기 있습니다
```

### 바로 열어볼 수 있는 것 두 개

설치도 실행도 필요 없습니다. **더블클릭만** 하면 됩니다.

| 파일 | 무엇 |
| :-- | :-- |
| `TAEYUN/eureka-공유용.html` | 프로토타입 · 화면 13개 전부 동작 |
| `TAEYUN/에이전트_흐름도.html` | 에이전트 설계 그림 5개 |

> ⚠️ `TAEYUN/prototype/` 소스를 직접 돌리려면 `npm install`이 필요합니다.
> 설치 파일(435MB)은 깃에 안 올라가 있습니다.

## STEP 2 — AI에게 맥락 넘기기

새 AI 세션을 열고 **아래를 통째로 복사**해서 던지세요.

```text
이 저장소는 "유레카(Eureka)"라는 AI 에이전트 기반 웹 서비스의 기획·설계 산출물이다.
팀명은 목욕중이고, 나는 이 팀의 팀원이다.

아래 순서로 파일을 읽고 전체 맥락을 파악해줘.
아직 코드는 건드리지 말고, 읽기만 해.

[1단계 — 무엇을 만드는가]
1. TAEYUN/Eureka_PRD_v2.md          기능 정의서. 5절·6절·10절을 특히 자세히
2. TAEYUN/flow_diagram_abstract.png  화면이 어떻게 이어지는지

[2단계 — 어떻게 생겼는가]
3. TAEYUN/에이전트_흐름도.html        에이전트 설계를 그림으로
4. TAEYUN/유레카_임시_DESIGN.md       디자인 규칙

[3단계 — 어떻게 만들 것인가]
5. TAEYUN/아키텍처_설계.md            시스템 설계 전체
6. TAEYUN/논의_01_에이전트와_스택.md   왜 이 스택을 골랐는지

[4단계 — 지금 어디까지 왔나]
7. TAEYUN/팀원과공유.md               현재 상태와 결정 안건
8. TAEYUN/prototype/README.md         프로토타입 구조
9. TAEYUN/prototype/src/              폴더 구조만 훑어보기

다 읽고 나서 아래를 정리해줘:

1. 이 서비스가 무엇이고 누구를 위한 것인지
2. 에이전트가 몇 개이고 각각 뭘 하는지
3. 배치와 실시간이 왜 나뉘어 있는지
4. 지금 어디까지 됐고 뭐가 안 됐는지
5. 아직 안 정해진 것 중 지금 정해야 하는 것
6. 네가 보기에 이 설계에서 위험하거나 빠진 지점

그 다음 내 지시를 기다려줘. 먼저 코딩하지 마.
```

**왜 이렇게 하냐면** — AI가 파일을 아무 순서로나 읽으면 맥락이 꼬입니다.
"무엇을 → 어떻게 생겼는지 → 어떻게 만들지 → 지금 어디까지"
순서로 읽어야 제대로 이해합니다.

마지막 6번(위험 지점)을 꼭 넣으세요. 우리가 놓친 걸 잡아줍니다.

## STEP 3 — 역할별로 이어서 던지기

STEP 2를 먼저 던진 다음, 자기 역할에 맞는 걸 이어서 씁니다.

### 기획

```text
나는 기획을 맡았다.

PRD 10절 TBD에 15개 항목이 남아 있다.
이 중에서:
- 지금 당장 정해야 개발이 안 막히는 것
- 개발하면서 정해도 되는 것
- 나중에 데이터가 쌓여야 정할 수 있는 것

이렇게 3개로 나눠줘.

그리고 각 항목마다 "이걸 정하려면 무엇을 알아야 하는지"도 알려줘.
```

### 백엔드

```text
나는 백엔드를 맡았다.

아키텍처_설계.md의 Phase 0(폴더 구조 · 스키마 · API 계약)부터 시작하려고 한다.

먼저 코딩하지 말고:
1. 만들 테이블과 컬럼을 구체적으로 제안해줘
   (PRD 8절의 "숫자는 DB 집계에서만" 원칙을 반드시 지킬 것)
2. 프론트엔드가 호출할 API 목록과 요청·응답 형태를 정의해줘
3. 이 중 지금 정보가 부족해서 못 정하는 게 있으면 물어봐

내가 승인하면 그때 코드를 만들자.
```

### 프론트엔드

```text
나는 프론트엔드를 맡았다.

TAEYUN/prototype/ 에 Next.js로 만든 화면 13개가 있다.
아키텍처_설계.md는 이걸 Vite로 옮기는 걸 전제로 쓰여 있다.

먼저 코딩하지 말고:
1. prototype/src/ 구조를 읽고, 옮길 때 그대로 가는 것과 바뀌는 것을 구분해줘
2. lib/nav.tsx 가 왜 있는지 파악하고, 이전 후에도 이 구조를 유지할 방법을 알려줘
3. 공유용 단일 HTML 빌드가 Vite에서 어떻게 되는지 알려줘

특히 3번이 중요하다. 서버 없이 열리는 파일 하나는 계속 유지해야 한다.
```

### 데이터 수집

```text
나는 데이터 수집을 맡았다.

PRD F00의 수집 파이프라인을 만들려고 한다.
데이터 소스 조사는 팀 저장소의 eureka/docs/DATA_SOURCES.md 에 있다.
(같이 안 받아졌으면 박민규 브랜치에서 가져올 것)

먼저 코딩하지 말고:
1. 네이버·카카오 검색 API로 실제로 "불편"이 담긴 글을 뽑아내려면
   어떤 검색어 전략이 필요한지
2. 수백 건을 모았을 때 비슷한 것끼리 묶는 방법을 비교해줘
   (임베딩+클러스터링 / LLM에게 통째로 / 둘 다 섞기)
3. API 한도 안에서 문제 10~20개를 만들려면 몇 건이나 모아야 하는지 추정

2번이 기술 스택을 가르는 지점이라 제일 중요하다.
```

## STEP 4 — 작업 시작할 때

결정이 끝나고 실제로 만들 때 던지는 프롬프트입니다.

```text
이제 위 설계를 바탕으로 실제 구현을 시작하자.

개발 원칙:
- 데이터 schema를 먼저 정의한다
- Backend API 계약을 먼저 고정한다
- AI Agent는 역할별로 분리한다
- Agent가 외부 API를 직접 호출하지 않고 tools를 통해 호출한다
- Prompt는 prompts 폴더에 분리한다
- Workflow는 graph 폴더에서 관리한다
- mock 데이터로 UI를 먼저 검증한 뒤 실제 API와 연결한다
- LLM 출력 스키마에는 숫자 필드를 두지 않는다 (숫자는 DB 집계에서만)
- 각 단계마다 실행 가능한 상태를 유지한다
- 단일 HTML 공유본이 계속 빌드되는지 확인한다

Phase 0부터 시작해줘. 한 단계 끝날 때마다 멈추고 나에게 확인받아.
```

> 마지막 줄이 중요합니다.
> 한 번에 다 만들게 하면 나중에 되돌리기 어렵습니다.

## STEP 5 — 다른 AI로 검증하고 싶을 때

`TAEYUN/프롬프트_유레카.md` 를 쓰세요.
GPT·Gemini 등에 던져서 다른 설계안을 받아보고 비교하는 용도입니다.

그 문서 5절에 **답변 채점표**가 있습니다.
대부분의 AI가 아래 7개를 빠뜨리니, 그걸로 걸러내면 됩니다.

- 배치와 실시간을 분리했는가
- 숫자를 LLM이 못 만들게 하는 장치가 있는가
- 근거와 AI 설명이 데이터 모델에서 분리되어 있는가
- 검증점수를 만들어내지 않았는가
- 같은 입력 → 같은 결과가 보장되는가
- 진행 상태 스트리밍이 API 설계에 반영됐는가
- mock 전용 경로가 살아있는가
