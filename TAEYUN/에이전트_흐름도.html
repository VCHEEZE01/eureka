가장 단순하게

에이전트는 넷뿐입니다

복잡해 보이지만 실제로 판단하는 주체는 네 개입니다. 앞의 둘은 재료를 만들고, 뒤의 둘은 결과를 만듭니다.

F05(문제 조합)와 F07(개인화)은 별도 에이전트가 아닙니다. 같은 생성기에 입력이 하나 더 붙을 뿐입니다. 이 점이 설계를 크게 단순하게 만듭니다.

여기서 얻는 것

기능이 F00부터 F07까지 여덟 개지만 만들 에이전트는 네 개입니다. 뒤의 두 생성기를 입력만 바꿔서 재사용하기 때문입니다. 아래는 이 네 개가 실제로 어떻게 돌아가는지 자세히 본 것입니다.

언제 도는가

축이 두 개입니다

대부분의 AI 서비스는 "사용자가 누른다 → AI가 답한다" 하나뿐입니다. 유레카는 그 앞에 미리 돌려두는 축이 하나 더 있습니다. 그리고 유레카의 핵심 가치인 "근거 데이터"가 바로 그 미리 돌려두는 쪽에서 나옵니다.

이 그림이 왜 중요한가

배치와 실시간을 한 덩어리로 만들면, 수집이 실패했을 때 서비스 전체가 멈춥니다. 반대로 제대로 나누면 수집이 밤새 죽어 있어도 사용자는 아무 문제 없이 씁니다. 폴더 구조와 서버 구성이 여기서 갈립니다.

F00 · 배치

문제를 만드는 과정

인터넷에 흩어진 글을 긁어와서 "이건 하나의 문제다"라고 정리하는 과정입니다. 7단계를 거치고, 마지막에 세 갈래로 갈립니다.

이 세 갈래가 있기 때문에 단순한 순차 실행이 아니라 워크플로우 도구(LangGraph)가 필요합니다.

여기서 팀 결정이 필요합니다

묶기가 이 파이프라인에서 가장 어렵고, 기술 스택을 가르는 지점입니다. 그리고 검수의 세 갈래를 AI가 알아서 판단할지, 사람이 확인할지가 안 정해져 있습니다. 사람이 본다면 관리자 화면이 하나 더 생깁니다 — PRD에도 플로우 다이어그램에도 없는 화면입니다.

F05 · F07 · 실시간

사용자가 기다리는 동안

사용자가 "개인화하기"를 누르면 그 자리에서 아이디어를 만듭니다. 수 초가 걸립니다. 그동안 빈 화면을 보여주면 안 되므로, 각 단계가 끝날 때마다 화면으로 알려줍니다. 프로토타입에 이미 넣어둔 진행 상태 UI가 이것입니다.

기능단계사용자가 보는 것
리서치 범위F02 범위 확인 → 소스별 수집 → 신호 해석 → 중복 정리 → 목록 구성 처음 고른 범위일 때만 대기
문제정의 조합F05 문제 읽기 → 공통점 찾기 → 새 문제정의 쓰기 → 근거 정리 2~3개를 합친 새 문제
개인화F07 기준 읽기 → 후보 모으기 → 고치기 → 설명 → 범위 조정 조건에 맞는 아이디어 3~5개
