## 6. 앞으로의 진행 순서

각 단계가 끝날 때마다 **돌아가는 상태**를 유지합니다.

| Phase | 내용 | 끝나면 |
| :-- | :-- | :-- |
| **0** | 폴더 구조 · 데이터 스키마 · **API 계약 고정** | 프론트/백이 따로 일할 수 있게 됨 |
| **1** | Tool → Prompt → Agent → Workflow (조합·개인화) | 에이전트가 진짜로 돎 |
| **2** | API 연결 + 진행상태 스트리밍 + 테스트 | 백엔드 완성 |
| **3** | 프론트엔드 연결 | **여기서 한 번 완결 — 발표 가능** |
| **4** | 실제 데이터 수집 파이프라인 | **진짜 데이터로 교체** |
| **5** | 캐시 · 로그인 · 마무리 | MVP 완성 |

**Phase 0이 제일 중요합니다.** API 계약만 고정되면 프론트와 백엔드가 서로 안 기다리고 병렬로 갈 수 있습니다.

**Phase 3에서 한 번 완결됩니다.** 여기서 멈춰도 발표할 게 있습니다. Phase 4가 유레카의 핵심 주장("실제 데이터 기반")을 증명하는 단계고요.
